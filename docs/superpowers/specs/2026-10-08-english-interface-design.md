# 中英文管理界面

用户要求在已同意的 SaaS 升级中补上英文界面。沿用现有产品、布局、租户边界和 API 契约，在合并前一起验证。

## 范围与取舍

采用本地 ESM 翻译字典和显式翻译调用，覆盖登录/注册、导航、九个管理页面、弹窗、参数帮助、状态、错误信息、日期显示以及 API 参考页。另一个选择是引入 i18next 一类框架，但现有项目不需要因此增加运行依赖。全局替换渲染后的 DOM 文本会误译用户资料，因此不用这种方式。

界面提供 `zh-CN` 与 `en`，默认中文，记忆用户选择。切换入口在登录页和已登录页面可见，API 参考页也可切换。更新 html 的 lang 与页面标题。存储不可用时仍能通过 URL 中的 lang 参数保持当前选择。语言切换重新载入当前页面和路由；载入前给用户明确确认，提醒保存尚未提交的编辑以及进行中的请求可能中断。取消时不更改语言或存储，也不重新载入。

只翻译软件界面文案。组织名、知识库与文档内容、提问、回答、引用、用户标签、自定义节点名、已保存提示词和工作流 JSON 不因切换而改变。新建节点可以使用所选界面的默认显示名称，已有图中的名称和配置必须保持原文。请求字段、状态枚举、模型协议、资源 ID 与业务数据保持现有契约。

## 实现边界

共享模块提供语言读取/保存、纯文本翻译 `t`、安全的静态模板翻译 `html`、静态页面标注翻译以及切换入口绑定。翻译只作用于静态模板片段；插值中的业务数据不经过字典替换。生成参数和检索参数的技术标识（例如 top_p）保持原名，其中文说明要有英文版本。日期使用当前语言格式。友好错误与配额提示提供两种语言；未知服务端错误保留原文。

无远端翻译、无新运行依赖、不读取私人环境文件或 LangBot 数据。复用现有隔离 worktree，原工作目录保持原有修改。本轮只修改前端与相关测试和文档。

## 验证与交付

测试先验证英文导航/表单/错误与参数帮助缺失，再实现；覆盖语言持久化、非法值和不可用存储、取消切换、转义以及中文业务数据插值保持原样。执行完整 Node 测试与各浏览器模块语法检查。浏览器用合成租户检查两种语言的登录、导航、编排和参数帮助，并保留安全截图。英文 UI 在窄屏不得产生页面横向溢出。独立审查通过后更新现有 PR；最新 Windows/Linux CI 通过后按用户同意合并 main。
