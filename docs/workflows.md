# 可视化知识编排

管理端把检索范围、证据处理和模型调用放在同一张流程图中。不同场景可以分别保存、发布和回滚；团队成员使用已发布版本，编辑者可继续修改草稿。

## 建立第一个流程

1. 在知识库页面导入资料，等待导入任务完成，并用检索预览确认能找到相关片段。
2. 由 owner/admin 在模型连接页面添加 OpenAI Chat Completions 兼容服务。填写实际地址、模型 ID、环境变量引用及默认参数，执行连接测试。部署者需要提前配置主机和凭据引用允许列表。
3. 打开可视化编排，选择“严格证据客服”模板。在检索模块选择知识库，在模型模块选择模型连接，分别点击“应用参数”。
4. 校验结构与资源，保存草稿，再输入合成问题试运行。检查回答来源与节点轨迹后发布版本。

模块可以从左侧拖入画布，也可点击添加。拖动输出端口到兼容输入端口，或依次点击两个端口建立连接；选中模块后可调整参数、删除模块。画布支持平移、缩放、适配、撤销和重做。导入的 JSON 仍须通过当前组织资源校验。

## 可组合模块

| 模块 | 主要配置 | 执行作用 |
| --- | --- | --- |
| 问题输入 | 本次问题 | 把输入传给下游 |
| 知识库检索 | 多知识库、Top K、混合权重、阈值、重排、上下文预算 | 在所选知识库范围内检索，并经 SQL 校验可见片段 |
| 元数据过滤 | 字段与值的 JSON 对象 | 按片段实际元数据精确匹配，字段须已存在 |
| 去重与截断 | 保留数、字符预算 | 合并检索分支，去除重复片段并限制上下文 |
| 相关性重排 | 保留数 | 调用部署已启用的本地重排能力 |
| 证据门控 | 最少来源数 | 证据不足时阻止依赖它的模型调用 |
| 提示模板 | 系统提示 | 设置任务要求；平台仍附加不可信资料与引用约束 |
| 模型生成 | 连接、温度、Top P、输出 Token、超时 | 使用指定模型与实际参数生成回答 |
| 多模型融合 | 并列展示或主模型综合 | 合并模型分支；综合模式增加一次模型调用 |
| 回答输出 | 上游连接 | 返回回答、来源和运行状态 |

“多知识库汇总”模板提供两条检索分支，各自选择范围和参数，再去重、门控和生成。“多模型并行融合”模板让两条模型分支使用各自连接和参数，再合并结果。多模型一致不能代替事实核查，仍应检查引用与原文。

Embedding 模型与索引维度由部署者统一配置；管理端不能直接改变共享索引的维度。重排模块需要部署开启对应能力，未启用时校验会给出错误。

## 草稿、发布与运行

草稿允许尚未完成的连线和资源选择；填写的知识库或模型 ID 必须属于当前组织。发布、显式校验和运行要求完整有效的图：一个输入、一个输出，无环路、重复或悬空连接，每个模块都位于输入到输出的路径上。

发布生成不可变的图版本。修改草稿不会改变已发布图；回滚只切换发布指针，保留正在编辑的草稿。版本保存所选模型连接 ID；管理员修改或删除该连接会影响引用它的版本，运行前仍会重新校验，单次运行使用已捕获的连接配置。viewer 只能查看和运行已发布流程，editor 可编辑与发布，模型连接由 owner/admin 管理。

试运行使用异步任务：创建后显示等待与运行状态，持续读取服务器记录。取消先发出请求，收到服务器终态后才显示“已取消”。断线或轮询超时会显示状态未确认，可从运行记录重新核对。部分模型分支失败但仍有可用回答时会标记为降级，显示成功结果和失败轨迹。

节点轨迹提供状态、耗时、结果数和配置引用；回答来源单独展示。轨迹不记录密钥、原始提示或文档正文。导出图包含资源 ID 和配置，不包含凭据值；导入其他组织时需要重新选择对应资源。

## 执行边界

每张图最多 40 个模块、80 条连线、6 次模型调用。默认整次运行时限 180 秒，所有模型模块配置的输出 Token 总预算为 16,384；综合模型也计入预算。部署者可调整有界的 `WORKFLOW_TIMEOUT_SECONDS` 与 `WORKFLOW_OUTPUT_TOKEN_BUDGET`，不能通过拆分分支绕过校验。

检索与去重模块的上下文预算为 1,000–50,000 字符；最终模型上下文仍受平台预算约束。回答、对外来源与引用校验使用模型实际收到的证据范围。证据不足不会调用后续依赖模型，也不会作为成功回答计入问答额度。

连接测试只确认当前服务接受了合成请求，无法证明模型适合实际业务。发布前用自己的代表性问题在检索实验室比较参数，并按[评测指南](evaluation.md)人工检查忠实度、拒答质量和资料中的恶意指令。
